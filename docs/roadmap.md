# ClearTranslate Roadmap

## 版本策略

ClearTranslate 采用“代码支持四端，开发分阶段验证”的策略。

优先顺序：

```text
Windows / macOS 桌面端 -> Android -> iOS -> 语音和高级体验
```

原因：

- 长文本翻译和复制粘贴在桌面端使用频率更高
- 桌面端更适合验证核心价值
- 移动端需要单独优化交互，不应只是桌面 UI 的缩小版

## Phase 0：产品原型与技术验证

目标：确认 Flutter 项目、基础 UI、设置存储和 OpenAI-compatible 翻译链路可跑通。

交付内容：

- Flutter 项目初始化
- 首页静态 UI
- 设置页静态 UI
- API Key 本地保存验证
- OpenAI-compatible API 调用验证
- 输入文本并返回翻译结果
- 至少一个桌面端运行成功
- 至少一个移动端模拟器运行成功

验收标准：

- 输入英文可翻译成中文
- 输入中文可翻译成英文
- API Key 不写死在代码里
- 桌面和手机尺寸下 UI 不崩

## Phase 1：MVP 文本翻译版

目标：做出日常可用的第一版。

功能范围：

- 文本输入
- 自动识别中英
- 手动切换语言
- 翻译结果输出
- 一键复制
- 一键清空
- 基础错误提示
- 本地历史记录
- 设置默认模型
- 深色模式
- 桌面快捷键

优先平台：

- Windows
- macOS

验收标准：

- 可替代日常 50% 以上网页翻译需求
- 长段落不会明显丢格式
- API Key、网络、模型返回失败等错误信息可理解
- 主流程无明显卡顿

## Phase 2：长文本增强与词典模式

目标：形成 ClearTranslate 的核心差异点。

功能范围：

- 长文本自动分段
- 翻译进度显示
- 取消翻译
- 分段失败重试
- 保留 Markdown
- 术语一致性提示
- 单词自动识别
- 词典模式结构化输出
- 收藏词典查询结果
- 历史搜索

验收标准：

- 输入长篇英文文章可稳定翻译
- 输入 `set`、`run`、`charge` 等多义词时，输出明显优于普通单句翻译
- 翻译过程中可以取消，不会卡死 UI

## Phase 3：移动端适配

目标：让 Android 和 iOS 成为真正可用版本。

功能范围：

- 移动端首页重构
- 输入区和输出区上下布局
- 底部导航
- 移动端复制体验优化
- 长按菜单
- 系统分享入口
- 从其他 App 分享文本到 ClearTranslate
- Android 打包
- iOS 打包

验收标准：

- 手机上单手可用
- 从浏览器、邮件、聊天软件复制文本后，打开 App 可以快速翻译
- 移动端不出现桌面 UI 压缩导致的拥挤感

## Phase 4：语音输入

目标：加入短句语音输入能力。

功能范围：

- 点击麦克风输入
- 语音识别为文字
- 识别完成后自动翻译
- 支持中英文语音输入
- 麦克风权限处理
- 识别失败提示
- 移动端优先优化

取舍：

- 只做短句和日常表达
- 不做长时间录音
- 不做会议转写
- 不做音频文件上传转写

## Phase 5：体验优化

目标：让 ClearTranslate 成为长期使用也不打扰的工具。

功能范围：

- 快捷键完善
- 系统托盘
- 小窗模式
- 最近一次翻译恢复
- 收藏夹
- 导出历史
- 清理历史
- 翻译风格模板
- 自定义 Prompt
- 术语表

验收标准：

- 打开速度和操作效率优于常用网页翻译
- 复制、粘贴、翻译、复制结果的流程稳定在几秒内完成
- UI 长时间使用不造成视觉疲劳

## Phase 6：可选发布路线

### 路线 A：个人工具

不做账号、不做后端、不做支付。用户自行填写 API Key，客户端负责翻译、历史和设置。

适合：

- 个人长期使用
- 小范围开源
- 降低维护成本

### 路线 B：公众发布

增加服务端和商业化能力。

可能需要：

- 账号系统
- 服务端代理
- 用量统计
- 支付系统
- 隐私政策
- 服务条款
- 额度限制
- 日志系统
- 滥用防护

该路线复杂度显著上升，不建议早期进入。
